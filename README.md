# Bridge: Suvvy.ai ⇆ Carrot Quest

Мост между виджетом Carrot Quest на сайте refettorio.ru и ИИ-ботом Suvvy.ai. Схема потока сообщений — в [../docs/integration.md](../docs/integration.md).

**Важно про архитектуру:** в Carrot Quest нет системного события "новое сообщение от посетителя" — проверено вручную по всем разделам админки (Интеграции → Webhooks, Чат-боты, Триггерные сообщения → Условия отправки, полный список системных событий) и подтверждено документацией. Есть только статистика по **исходящим** триггерным рассылкам (доставлено/прочитано/был клик/ответил на рассылку) — это не то же самое, что входящее сообщение живого посетителя в открытом диалоге. Поэтому вместо ожидания вебхука от Carrot Quest мост сам **опрашивает** её API на новые сообщения (поллинг). Направление Suvvy → мост осталось вебхуком как было — там всё работает.

## Файлы
- `app.py` — Flask-сервер: `/poll/tick` (запустить один проход опроса вручную/по cron), `/webhook/suvvy` (сюда Suvvy шлёт готовый ответ ИИ)
- `poller.py` — сам опрос: какие диалоги смотреть, как передавать в Suvvy, дедупликация по id реплики
- `carrotquest_client.py` — Carrot Quest Web API: список диалогов с непрочитанными репликами посетителя, реплики диалога, отправка ответа
- `suvvy_client.py` — отправка сообщения посетителя в Suvvy
- `dedup.py` — защита от повторной пересылки одной и той же реплики/сообщения
- `config.py` — настройки из `.env`
- `test_offline.py` — тесты без реальных аккаунтов (все запросы наружу подменены моками)

## Запуск локально
```
python -m venv venv
venv/Scripts/pip install -r requirements.txt   # или venv/bin/pip на Linux/Mac
cp .env.example .env   # и вписать реальные токены
venv/Scripts/python app.py                     # или venv/bin/python на Linux/Mac
```
Сервер поднимется на `http://localhost:8000` (порт — из `.env`) и сразу запустит фоновый поток опроса Carrot Quest (интервал — `POLL_INTERVAL_SECONDS`, по умолчанию 5 сек). Это подходит для постоянного хостинга (VPS) — там опрос просто крутится сам, пока жив процесс.

## Проверка без реальных доступов
```
venv/Scripts/python test_offline.py
```
Прогоняет все сценарии (поллинг находит новую реплику и передаёт её в Suvvy, повторный опрос той же реплики не дублирует пересылку, диалоги без непрочитанных реплик пропускаются, `/poll/tick` защищён секретом, ответ от Suvvy уходит обратно в Carrot Quest) на моках — реальные Carrot Quest/Suvvy не нужны.

## Что нужно для настройки на реальных аккаунтах
1. **Carrot Quest**, раздел "Разработчикам": взять `auth_token` приложения (формат `app.<id>.<секрет>`) → `CARROTQUEST_AUTH_TOKEN`. Отдельный `app_id` в конфиге не нужен — извлекается из самого токена.
2. **Suvvy.ai**:
   - Каналы → Персональный канал (API) → указать URL: `https://<хост-моста>/webhook/suvvy`
   - скопировать выданный токен → `SUVVY_API_TOKEN`
   - задать секретное слово → `SUVVY_WEBHOOK_SECRET`
   - выполнить тестовый запрос из интерфейса Suvvy — сервер моста должен ответить 200
3. Свой секрет для `/poll/tick` → `POLL_SECRET` (любая случайная строка, не связана ни с Carrot Quest, ни с Suvvy — просто чтобы посторонний не мог дёргать наш эндпоинт и тратить квоту Suvvy).

## Деплой (тест на Vercel)
Для быстрого теста, не дожидаясь решения по постоянному хостингу — деплоим на Vercel. Код уже подготовлен под их serverless-рантайм: `api/index.py` (точка входа) и `vercel.json` (роутинг всех путей на неё), `dedup.py` при деплое на Vercel сам переключается на запись в `/tmp` (обычный диск там read-only).

```
cd bridge
npx vercel login          # откроет браузер для входа/регистрации
npx vercel                # первый деплой — ответить на вопросы по умолчанию (Enter), это создаст проект
```

Дальше вписать переменные окружения (значения — из локального `.env`, руками через дашборд vercel.com → проект → Settings → Environment Variables, или через CLI):
```
npx vercel env add CARROTQUEST_AUTH_TOKEN production
npx vercel env add SUVVY_API_TOKEN production
npx vercel env add SUVVY_WEBHOOK_SECRET production
npx vercel env add POLL_SECRET production
npx vercel --prod         # передеплой, чтобы функция подхватила переменные
```

**Важное отличие serverless-деплоя:** на Vercel фоновых процессов между запросами нет — поток из `if __name__ == "__main__":` там не запускается (Vercel вызывает WSGI-приложение из `api/index.py` напрямую, без этого блока). Поэтому опрос нужно дёргать снаружи — вызывать `POST /poll/tick` с заголовком `Authorization: Bearer <POLL_SECRET>` по расписанию:
- **Vercel Cron** — но на бесплатном (Hobby) плане минимальный интервал — раз в сутки, для чата это слишком редко;
- **Внешний cron** (например, [cron-job.org](https://cron-job.org), бесплатно) — можно каждую минуту, для теста ок, но всё равно не мгновенно;
- По-настоящему быстрый отклик посетителю — только на постоянном хостинге с фоновым потоком (см. раздел ниже), поэтому для реального запуска (не теста) лучше сразу переезжать туда.

## Постоянный хостинг (на будущее)
Когда решится вопрос с постоянным сервером (см. [../CLAUDE.md](../CLAUDE.md)) — там `app.py` запускается напрямую (`python app.py`), фоновый поток опроса стартует сам при запуске, `api/`/`vercel.json`/внешний cron для этого не нужны, дедупликация пишет в обычный файл без `/tmp`. Это же самое время, чтобы уменьшить `POLL_INTERVAL_SECONDS` для более быстрого отклика (5 сек — разумный компромисс, меньше — больше нагрузка на API Carrot Quest).

## Ограничения текущей версии
- Не проверялось на реальных Carrot Quest/Suvvy — только по документации и офлайн-тестами.
- Опрос идёт по всем диалогам приложения с непрочитанными репликами посетителя — при большом объёме одновременных диалогов стоит проверить лимиты Carrot Quest Web API на частоту запросов (rate limits) и при необходимости увеличить `POLL_INTERVAL_SECONDS`.
- Дедупликация — по `id` реплики диалога (у Carrot Quest он есть в отличие от старой вебхук-схемы, так что дедуп теперь точный, не приблизительный).
- Нет очереди/ретраев на исходящие запросы — если Suvvy или Carrot Quest недоступны в момент запроса, сообщение просто теряется (лог пишется, но нет повторной попытки). Для недельного MVP это допустимо, но стоит иметь в виду.
